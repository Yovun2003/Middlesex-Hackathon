# NouDilo world assets

All buildings, vehicles, palms, and equipment in `public/models` are original procedural Three.js assets generated by `scripts/generate-assets.mjs`. They use physically based materials. No paid assets or generation services are required. These generated model assets are dedicated under CC0-1.0; the repository's other material retains its own licensing.

The geometry is authored in `scripts/generate-assets.mjs`, then welded, bevelled, normal-weighted, and exported using Blender 4.5.9 LTS through `scripts/refine-assets.py`. The editable Blender scene is `assets/source/noudilo-neighbourhood.blend`; each asset has its own collection. These are authored models rather than scanned architecture. Building and service placement is illustrative, not a cadastral or utility survey.

To regenerate the complete pipeline with a locally installed Blender:

```sh
npm run assets
blender --background --python scripts/refine-assets.py -- "$PWD"
```

The bundled files are already refined; running only the first command produces the intermediate procedural assets. Blender is needed for asset authoring, not application runtime or normal builds.

Ground and plaster use [Aerial Grass Rock](https://polyhaven.com/a/aerial_grass_rock) and [Concrete Wall 006](https://polyhaven.com/a/concrete_wall_006) material maps from Poly Haven. Their [CC0 licence](https://polyhaven.com/license) permits bundling. Source URLs, checked source checksums, and local byte counts are recorded in `public/textures/manifest.json`. The six 1K maps are converted to WebP (1.50 MB total, down from 4.72 MB source JPEGs). `scripts/optimize-textures.mjs` documents the one-time conversion; it takes the source JPEGs named in the manifest and uses a local Chrome installation. The concrete albedo is lightened to suit mineral plaster while retaining the source normal and roughness maps.

The renderer batches each model by material and instances repeated homes and palms. Low detail mode reduces house/palm counts, terrain tessellation, pixel ratio, and shadow resolution. Scene assets are loaded through a deferred module and GLTF cache; camera changes do not reload them. Lighting uses a generated sky, hemispheric fill, directional shadows, and local lightformers, with no external HDR dependency. Roughness/bump detail is procedurally generated.

Existing terrain assets use Mapzen elevation data and Natural Earth shoreline data:

- [Mapzen terrain tiles](https://registry.opendata.aws/terrain-tiles/)
- [Natural Earth physical vectors](https://www.naturalearthdata.com/downloads/10m-physical-vectors/)
- [OpenStreetMap attribution and license](https://www.openstreetmap.org/copyright)

The world combines a recognisable island terrain mesh with local ground, roads, intersections, rooftop tanks, depot storage, a reservoir, public pipes, vehicles, and maintenance equipment. House networks indicate an illustrative grouping, not measured affected-property boundaries. Tank levels are symbolic duration feedback. The route is demonstration playback and never safe navigation or GPS telemetry.

The interface design applies the supplied Unslop guidelines by Damir Sokolovsky ([@heydamir](https://x.com/heydamir), CC BY 4.0), alongside the supplied Prism and Awwwards guidance. Their missing companion reference folders and verifier scripts were replaced with the project's browser, accessibility, and performance checks; no absent tool was claimed as run.
